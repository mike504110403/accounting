# ADR-0008 帳務規則 v1.4（每月補入額、預算改影子紀錄、月清帳）

日期 2026-09-04　狀態 accepted（取代 ADR-0007 的「用預算支付」、信封預扣、撥款可退回、個人期初餘額；ADR-0007 其餘條款仍有效）

## 情境

v1.3 上線 TestFlight 後 Mike 重述帳務八條：個人餘額改為「每月預留一筆給共同支出」的額度制，預算不再是資金來源而是評估共同花費的影子紀錄，另需「清帳」把已結束月份的個人餘額偏差列成明細後歸零。與 v1.3 的差異集中在個人餘額有了「月」的概念、預算與餘額脫鉤、以及一張新的清帳紀錄表。

## 決策（十題裁示，2026-09-04）

1. **清帳的三方對帳**：清帳月每位成員的月末個人餘額＝每月補入額＋該月淨變動；正值＝該成員應轉這筆給共同帳戶，負值＝共同帳戶應補該成員。app 只列明細、只動個人餘額（把該月自公式排除），轉錢與記共同收入全部人工。成員間債務不在清帳裡算，仍走結算多簽；**該月所有拆帳（有付款人、非 common 的共同支出）全數 settled 才能清帳**。
2. **結算份額依帳目 occurred_on 逐筆歸月**：未結算的代墊由付款人全額負擔；結算完成後每位成員各負擔自己的份額（付款人淨負擔＝自己的份額）。不再用 `settlements.nets` 與 `settled_at`。
3. **個人期初餘額廢除**：欄位保留不用，UI 與公式拿掉；每月補入額取代。
4. **每月補入額**（`members.monthly_topup`，每人只能改自己的）：從加入帳本那個月起每月加一次；改值即時套用所有未清帳月份，不做逐月快照。
5. **預算「已花」＝該分類當月所有共同支出**（共同錢包付＋代墊），私人支出不算。
6. **每分類每月只能設定一次預算**：金額 > 0、建立後不可改不可刪不可退回。
7. **`entries.funding` 與 enum 整個 drop**；表單、結帳的資金來源列拿掉；沖銷不再抄資金來源。
8. **清帳規則**：只能清已結束月份（依台北時間早於當月）、必須按序（最早未清帳月起）、同月只清一次、不可撤銷、任一成員可執行不用多簽、走 security definer RPC 並寫 `month_closes` 紀錄表。
9. **已清帳月份鎖定**：occurred_on 落在已清帳月份的帳目（含分攤、細項）與撥款不可新增、修改、刪除（DB trigger；沖銷筆日期照抄原筆因此也被擋）。
10. **共同可用餘額不再扣信封**：共同餘額只由手動記的共同收入與共同錢包支出推動；撥款、清帳、結算都不動它。預算頁頂部與趨勢線語意跟著改。

## 後果

- DB：`members.monthly_topup`；`budget_allocation` 加月份 generated 欄＋每分類每月唯一、`amount > 0`、收回 UPDATE／DELETE；drop `entries.funding`＋`funding` enum＋check；`upsert_entry` 去 funding；新表 `month_closes`；RPC `close_month`／`month_close_preview`；已清帳月份鎖定 trigger；`month_summary` 依新公式重寫（個人餘額＝Σ未清帳月（補入額＋淨變動）、已花＝所有共同支出、shared_available＝shared_balance）。
- 前端：`balance_math` 重寫個人餘額與預算函式；models 去 `Funding`、加 `monthlyTopup`／`MonthClose`；表單／結帳／沖銷去資金來源；預算頁頂部四數字、撥款 sheet 改「設定本月預算」（一次、不可改）；設定頁「每月補入額」取代個人期初餘額、新增清帳入口；新清帳頁（列表＋預覽＋確認）；統計趨勢線改共同餘額／個人餘額（新公式）。
- 資料：migration 前把既有撥款依（帳本、分類、月）合併成一筆，合計 ≤ 0 者刪除。
- 部署順序照 ledger 定則：先 push migration 並驗證雲端，再發 app build。
